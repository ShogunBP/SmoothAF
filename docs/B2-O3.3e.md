# SmoothAF V2 — B2-O3.3e: parser TSV host-only e provenance

**Status:** parser host-only implementado e validado. Nenhuma alteração em `src/`, logger/FIO, ABI ou firmware. Não houve build ARM, teste físico, D1, ACTIVE CONTINUOUS, movimento de lente, HOLD, shadow mode, commit ou push.

## Resultado

O consumer atual grava linhas ASCII TSV de exatamente nove campos:

```text
timestamp_ms<TAB>event_name<TAB>episode_id<TAB>payload[0]<TAB>payload[1]<TAB>payload[2]<TAB>payload[3]<TAB>payload[4]<TAB>payload[5]<LF>
```

A implementação real está em `src/smoothaf_logger.c:513-540` (`event_name`) e `src/smoothaf_logger.c:586-623` (`format_record`). O logger não grava cabeçalho.

O campo `sequence` do registro binário não é emitido no TSV. A ordem física das linhas é preservada pelo parser, mas não é convertida em `sequence`.

## Arquivos criados

- `tools/b2o33e_tsv.py` — parser determinístico do TSV FIO real, conversão de `OBS_SNAPSHOT_V1`, estados de truncamento e integração com provenance.
- `tests/test_b2o33e_tsv.py` — fixtures e testes host-only.
- `docs/B2-O3.3e.md` — este relatório.

O contrato anterior de provenance em `tools/b2o33d_collection.py` foi reutilizado e estendido com `FIO_TSV9`. O parser não implementa `OBS_SESSION_START` no firmware.

## Schema confirmado

- Entrada tratada como bytes crus.
- Codificação aceita: ASCII. Bytes não-ASCII são rejeitados.
- Delimitador: tab (`0x09`).
- Terminador esperado: LF (`0x0A`). CRLF é aceito deterministicamente, removendo apenas o CR final.
- Cada linha precisa ter exatamente 9 campos.
- Não existe cabeçalho.
- Linha final sem LF é `PARTIAL_FINAL_LINE`/`TAIL_TRUNCATED` e rejeitada para coleta estrita.
- A posição física, número da linha, byte offset e bytes da linha são preservados.
- Timestamps iguais não são ordenados ou deduplicados.

Campos: `timestamp_ms` decimal `0..0xffffffff`; `event_name` token ASCII; `episode_id` decimal `0..0xffff`; seis payloads decimais. Cada `TsvRecord.sequence` é explicitamente `None`.

O mapa reproduz os casos nomeados de `event_name()` do C: eventos 1–24, incluindo `SESSION_START`, `SESSION_END`, eventos históricos, `MOVIE_GATE_REJECT` e `OBS_SNAPSHOT_V1`. O C também emite `UNKNOWN` para o tipo numérico 0 e para qualquer tipo não reconhecido; portanto, nem o tipo 0 nem o evento 25 podem ser recuperados desse texto. Nomes desconhecidos, mas sintaticamente válidos, são preservados com `event_type=None` e payload intacto. `UNKNOWN` não pode ser reinterpretado como `OBS_SESSION_START`.

## Signed/unsigned

O parser reproduz `src/smoothaf_logger.c:602-619`:

- `D1_SERIES_START`, slots 0–2: `uint32`;
- `D1_CONTEXT`, `D1_CONTEXT_AUX`, todos os slots: `uint32`;
- `MOVIE_GATE_REJECT`, todos os slots: `uint32`;
- `D1_SAMPLE`, slot 0: `uint32`;
- demais eventos: `int32`.

Valores fora do intervalo são rejeitados. `-1` é válido em campos signed e inválido nos campos que o C escreve como unsigned.

## OBS_SNAPSHOT_V1

Para `OBS_SNAPSHOT_V1` (`event_type=24`), o parser valida timestamp, episode e payload, reutiliza o decoder V1 para validar schema/fase/logical ID/sentinelas/flags, e expõe o snapshot com `sequence=None`. Um `sequence=0` interno é usado apenas para reutilizar o decoder e nunca é apresentado ou usado para pareamento.

BEFORE/AFTER e timestamps iguais permanecem na ordem física original.

## Sessões e provenance

`tools/b2o33e_tsv.py` reutiliza `source_id`, hash esperado/observado sobre bytes crus, tamanho, filename original, modo/contexto, cadeia de transferência, fronteiras conhecidas, `session_scope` e `marker_state`.

`SESSION_START`/`SESSION_END` segmentam lifecycle para impedir que chaves V1 atravessem um marcador. Eles não são UUID/boot ID. O resultado continua com `session_identity=UNAVAILABLE` e `eligibility=REJECT` para evidência de sessão.

Regras fail-closed:

- não inferir sessão por filename, timestamp, episode, logical ID ou ordem;
- arquivos misturados/concatenados exigem rejeição por provenance;
- BEFORE de um source e AFTER de outro não formam par;
- source duplicado é ambíguo;
- drops, truncação e linhas inválidas não são recuperados;
- `stable_metadata` permanece separado de identidade e independência de frame YUV.

A elegibilidade é separada por finalidade. Um artefato TSV íntegro, com provenance suficiente para a cópia local, pode ser usado para análise descritiva local mesmo sem identidade global; até um escopo de sessão ambíguo pode ser descrito sem parear através de boundaries. Isso não autoriza calibração operacional:

```text
validity                         = COMPLETE
pairing.status                   = COMPLETE
session_identity                 = UNAVAILABLE
descriptive_eligibility         = ACCEPT_LOCAL
operational_calibration         = REJECT
frame_independence_proven       = false
```

Se faltar provenance ou houver ambiguidade, ambas as finalidades são rejeitadas. `CollectionEligibility` legado permanece `REJECT` para não promover o TSV a evidência de sessão.

## Casos rejeitados

- número de colunas diferente de nove;
- timestamp, episode ou payload fora do intervalo;
- bytes não-ASCII;
- final sem LF;
- hash ou tamanho divergente;
- source ausente;
- escopo `MULTI_SESSION`, `CONCATENATED` ou `UNKNOWN`;
- marker metadata incompatível;
- chave V1 duplicada;
- BEFORE/AFTER incompleto;
- tentativa de promover `UNKNOWN` a event 25;
- timestamp wrap usado como identidade;
- ausência de sequence preenchida artificialmente.

## Compatibilidade e firmware

- ABI binário de 36 bytes inalterado.
- `OBS_SNAPSHOT_V1=24` inalterado.
- Nenhuma alteração em `MEASUREMENT`, `D1_SAMPLE`, logger/FIO ou firmware.
- Eventos históricos conhecidos permanecem identificáveis; desconhecidos válidos ficam opacos.
- Nenhum sequence ou token é inventado.
- A provenance B2-O3.3d foi reutilizada com formato `fio-tsv9`.
- Não há parser de USB nem presunção de acesso USB aos arquivos Magic Lantern.

Para interpretar o TSV atual, a necessidade de firmware é **nenhuma**. Se o evento 25 for futuramente integrado, será necessário um contrato TSV próprio que defina seu nome e a representação unsigned dos words; este parser não fará inferência.

## GO/NO-GO

- **GO host-only:** parser TSV e integração de provenance implementados.
- **GO condicional para coleta futura:** preservar arquivo original, hash, tamanho, manifest e cadeia de transferência; reutilizar o mesmo build para várias medições; evitar remoções frequentes do SD.
- **NO-GO para declarar pares estáveis de sessão:** V1 TSV não contém identidade de sessão.
- **NO-GO para identidade global e frame independence:** continuam irrecuperáveis.
- **NO-GO para commit e build ARM:** restrições da etapa permanecem.

A solução proporcional é coletar o conjunto necessário de logs com o mesmo build, transferir os arquivos e analisá-los no PC com este parser, sem nova instalação física para validá-lo.
